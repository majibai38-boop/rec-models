# 推荐模型 Benchmark 平台实施计划

更新日期：2026-11-25。以[第一阶段方案](recommendation-benchmark-platform-proposal.md)为准。本版用 P1 任务替代原 M0 → M4 的首期排程，短期只交付 **Skill 驱动的环境搭建 → 模型运行 → 性能采集，以及本机/指定机器归档和只读 Web 浏览**。本次是计划调整，不表示新增能力已经实现。

## 已有基础与仍待验证的事项

| 基础 | 当前状态 | 第一阶段用途 |
|---|---|---|
| 配置化设备盘点 | 已实现；有 Windows 主机采集及合成 GPU/NPU 测试；实际执行节点仍待验收 | 环境准备前探测机器、设备与版本 |
| 环境配方与离线规划 | 已实现严格合同、兼容性规则、矩阵展开和指纹；示例仍为 draft | 复用结构检查与正式测量前准入 |
| Benchmark 分支边界 | 已移除历史分析/估算实现，旧本地内容已备份 | 独立建设三步流程与归档浏览 |
| 当前回归 | 43 项盘点/规划测试已通过（2026-11-25 清理验收） | 后续改动时保护既有协议；不替代真实 GPU/NPU 测试 |

首个模型继续采用小型 DLRM，单卡、FP32、eager、固定步数 train step。一个 target 即可运行；先完成一个可用后端的闭环，再验证另一个后端。CUDA/Ascend 的支持声明逐项随真实硬件验收更新，不把“双端同时可用”作为每次运行的前提。

## 第一阶段任务与验收

| 任务 | 内容 | 依赖 | 完成证据 |
|---|---|---|---|
| P1-01 | Skill 主流程与最小运行/归档合同 | 现有 inventory/planning | 三步输入输出、阶段状态和失败分支明确；合同 round-trip 通过 |
| P1-02 | 环境搭建 | P1-01、可访问执行节点 | 真实设备盘点、已固定配方、环境准备及 smoke 日志 |
| P1-03 | 模型运行 | P1-02 | 小型 DLRM 在指定设备短跑，输入/状态可恢复，数值检查有记录 |
| P1-04 | 性能采集 | P1-03 | 正式测量原始样本、可复算指标及可选独立 trace |
| P1-05 | 本地与指定机器归档 | P1-01；真实端到端依赖 P1-04 | 默认本机和 SSH 归档通过，完整性校验、冲突和失败重试可验证 |
| P1-06 | Web 浏览与演示验收 | P1-05 | 浏览性能、预览日志/JSON、下载 trace；Skill 返回实际可访问链接 |

P1-05 可先用明确标识的测试产物实现归档，P1-06 可用同一合同开发页面；软件测试样例不计为真实性能结果。以交付批次推进，不继续沿用原 6–8 周的大平台首期承诺。

### P1-01：Skill 主流程与合同

- [ ] 新增 `skills/rec-benchmark/`，描述参数收集、三步调用、结构化错误处理、归档与结果返回；具体动作调用统一 Python 脚本。
- [ ] 定义独立 `recbench.workflow/v1`：引用 BenchmarkSpec、节点/环境配置，选择一个 target，配置归档目的地和 profiling 开关；不直接向严格 v1 BenchmarkSpec 添加未知字段。
- [ ] 明确执行默认本机；归档默认启动 Skill/CLI 的宿主机及入口工作区下 `benchmark-results/archive`，远端用 SSH 别名和绝对目录单独配置。
- [ ] 定义最小 `RunManifest / Metric / Artifact`：run/attempt、来源与指纹、阶段状态、指标单位/范围/有效性、文件相对路径/大小/hash。
- [ ] 明确分层校验：先环境准备，再生成数据/初始状态 hash 和 pilot 步数，正式测量前完整准入；原始请求与 resolved spec 分开保存。
- [ ] 确定设备本地互斥锁、超时、退出码和中断记录；重新运行用新 attempt，归档重试复用原 attempt。

验收：缺失/非法参数有明确原因；单目标不要求伪造另一端快照；阶段成功必须由脚本结果和实际产物证明；Skill 不是仅返回手工执行建议。第一阶段不承诺无人值守后台续跑。

**P1-01 实施进度（2026-11-26）：** 已实现 `benchmark_core/workflow/` 合同层：`recbench.workflow/v1` 校验与单目标解析（`check` / `resolve`）、原始请求与 `resolved_spec.json` 分开保存并复用 planning 的离线计划、五段分层准入（structure / environment / workload_state / pilot / measurement）、最小 `RunManifest / Metric / Artifact` 合同、设备本地互斥锁、退出码与中断记录，以及 `skills/rec-benchmark/SKILL.md` 流程骨架。执行合同测试 23 项、既有盘点/规划测试 43 项通过。环境准备、模型短跑、性能采集与归档脚本仍未实现，Skill 目前只能完成校验与解析，因此 P1-01 保持未勾选。

**P1-01 外部验证（2026-11-28）：** caw mode2 在 119 宿主机（device2）验证提交 `9615411`，9 项离线验收全部通过：4 项结构检查（workflow、planning spec、CUDA/Ascend 配方）、4 项单元测试（全量、inventory、planning、workflow）和 `workflow resolve` round-trip；0 文件修改，报告 `local_passed`，证据为 caw issue #37。同一提交在本机实测 66 项单测通过（28 + 15 + 23）。本验证只覆盖离线配置、测试与解析，不含 GPU/NPU 执行，也不改变 P1-01 的未勾选状态；环境搭建、模型运行、性能采集与归档仍待实现。

### P1-02：环境搭建

- [ ] 复用 inventory 采集当前节点；记录真实设备身份、OS、驱动、固件和可见性。
- [ ] 首期采用锁定容器镜像；为 CUDA/Ascend 分别登记目标设备适用的精确版本、兼容性依据、镜像 digest 与启动参数。
- [ ] 实现环境准备脚本：检查宿主机前提、拉取镜像（或受控构建并固定 digest）、设备透传、容器内包版本核对与算子 smoke。
- [ ] Skill 调用脚本并归档配置、版本与日志；已满足配方时复用，配置变更时重新检查。宿主机驱动升级保留为人工前提。

验收：环境可复现、容器内实际版本有证据；缺驱动/容器工具、无设备、配方冲突时停止并给出具体原因；不将采集器 Python 的包版本当作执行容器版本。

### P1-03：模型运行

- [ ] 实现小型 DLRM adapter、参数校验、固定输入生成和 checkpoint/optimizer/RNG/数据游标保存与恢复。
- [ ] 实现 CUDA/Ascend 设备选择与短跑；保存源码/数据/状态 hash，验证 forward、loss、backward 与更新。
- [ ] 为模型定义数值检查依据和容差，记录实际目标设备，拒绝静默 CPU fallback。
- [ ] Skill 在环境准备成功后调用短跑，保存 stdout/stderr、时长、退出码及失败证据。

验收：实际目标设备运行成功；相同初始状态和输入可重放；不支持的算子、OOM、数值失败都能保留证据；合成数据不冒充业务质量验收。

### P1-04：性能采集

- [ ] 实现独立 pilot，冻结测量 N 和协议；建议起点 warmup 50、5 次重复，记录各次实际步数/样本数和窗口时长。
- [ ] 每次重复恢复完整训练状态；计时窗口前后正确同步；优先完成明确的 end-to-end scope。
- [ ] 输出吞吐、窗口均摊 step 时间、可用内存峰值和原始样本；中位数/min/max 由同一脚本复算。
- [ ] 提供可选独立 profiling 重放：保存原始 trace、采集配置和元数据，不在正式测量中开启 profiler。
- [ ] 将 measure/profile/正确性状态分别写入 manifest；不支持的指标为 null 加原因，不生成伪造 P95/P99 或成绩。

验收：至少一个真实后端跑出可复算成绩，另一个按硬件可用性独立记录验收；宣称支持的 profiling 后端也要有真实 trace。采集失败不删除正式测量，质量未通过的结果不能显示成有效 benchmark。需要跨设备倍率时另查 workload 条件一致性。

### P1-05：本地与指定机器归档

- [ ] 实现本地暂存 → 完整性清单 → 归档发布，默认落入口机器的 `benchmark-results/archive`。
- [ ] 支持 `archive.transport=ssh`，通过已有 SSH/SFTP 将产物发送到指定机器；远端用轻量 Python helper 校验与原子发布，无常驻 Agent。
- [ ] 预检远端连接/目录权限/空间；临时上传和最终发布隔离，只有校验完成才发布 COMPLETE。
- [ ] 相同 run/attempt 和相同内容重试幂等；不同内容不得覆盖；传输失败保留本地证据并支持单独重试。
- [ ] 失败实验也可归档，manifest 明确缺失项；归档完成与模型/测量成功分别记录。
- [ ] Skill 返回归档位置和传输结果；只有配置了实际部署的 Web 地址时返回该运行的浏览链接。

验收：默认本机可用；指定 SSH 机器可查到同一组已校验文件；断线、损坏、空间不足、同 ID 内容冲突能明确报错；重试归档不重跑 benchmark。SSH 传输成功本身不足以认定归档成功。

**P1-05 本地进度（2026-11-28）：** 已实现 `benchmark_core/archive/` 的本地部分：staging / published 目录协议、`new` / `publish` / `verify` 命令、`artifacts.json` 与 `COMPLETE` 标记、发布前重新校验、相同内容幂等重试与不同内容冲突拒绝、失败实验归档；归档测试 13 项通过。SSH 传输、远端预检/发布和 Web 索引（P1-06）尚未实现，因此 P1-05 保持未勾选。

### P1-06：只读 Web 与完整演示

- [ ] 新增轻量 `benchmark_web`，直接读取配置的本地归档根目录；列表只索引已完整发布的归档，不依赖数据库。
- [ ] 列表支持模型、设备/后端、时间与状态筛选；详情展示配置、环境、测量范围、质量状态、重复结果和原始值。
- [ ] 按 artifacts 清单提供文件列表、JSON/文本日志预览和 trace/其他文件下载；不提供写入、删除或任务执行接口。
- [ ] 文件读取验证路径边界与实际文件，阻止路径穿越/符号链接越界；预览以文本显示，不执行归档 HTML。
- [ ] 默认本机监听，记录如何在归档机器部署；指定远端归档时，其 Web 服务读取远端本地目录，浏览器通过 HTTP 访问。
- [ ] 完成 Skill 三步 → 默认本机归档 → Web 浏览，以及 Skill 三步 → 指定 SSH 机器归档 → 该机器 Web 浏览的演示。

验收：网页数据与归档 JSON 一致；失败、跳过、缺失和无效结果有明确展示；删除/重建可选索引不会丢原始结果；未启动 Web 时 Skill 返回归档位置而非伪造链接。

## 交付批次与下一步

1. **批次 A：Skill + 本机三步。** P1-01 → P1-02 → P1-03 → P1-04，先完成一个真实后端；本地文件随每步落盘。
2. **批次 B：归档闭环。** 完成 P1-05，把本地与 SSH 作为同一产物协议的两种目的地，验证失败保留和重试。
3. **批次 C：浏览与后端覆盖。** 完成 P1-06，并在可用 GPU/NPU 上分别验收已实现能力；记录未验证部分。

下一项开发从 **P1-01 最小 workflow/归档合同与 Skill 流程** 开始，然后落地环境准备脚本；现有 inventory/planning 直接复用，不再先建设集中控制服务。
