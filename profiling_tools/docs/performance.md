# 解析性能与资源限制

## 当前优化

- 字段名规范化使用最多 4096 项的 LRU 缓存；不缓存可变事件参数或 trace 内容，保留别名优先级、同名覆盖与空值语义。
- 单次解析仅分类一次完整事件，复用 kernel 候选列表和 Task Type。先关联 CPU owner，再过滤 step，保留跨 CPU step 边界的异步 kernel。
- Web Worker 的内存限制统计分析进程及全部后代进程的 RSS，覆盖 Windows venv 启动器场景。退出中的进程忽略；无权读取内存时停止任务，不静默放弃限制。

## 实测记录（2026-09-28）

同一台 Windows 主机、Python 3.12.14，同一组约 699 MB 输入；GPU PID 2028020、NPU PID 22802，全部 step，包含通信任务。比较流程包含预检查、解析、映射、报告与校验，不含上传和索引构建。

| 阶段 | 优化前（秒） | 优化后（秒） |
| --- | ---: | ---: |
| 预检查 | 42.80 | 18.23 |
| GPU 解析 | 36.96 | 11.35 |
| NPU 解析 | 5.90 | 2.60 |
| 全流程 | 91.13 | 37.85 |

本次总耗时下降约 58%，约 2.4 倍加速。这是一次顺序运行对比，受系统负载和文件缓存影响，不代表所有数据的固定收益。

18 个 CSV 和 coverage_diagnostics.json 的 SHA256 完全一致；XLSX 的全部 ZIP 成员内容一致（不比较 ZIP 容器时间戳）。8541 项结果校验通过。输入原有的 68 个 NPU trace-only 任务排除警告仍保留。

## 已知限制

JSON 仍完整加载到内存，本次峰值 RSS 从约 2487 MiB 到 2542 MiB，没有改善。后续可评估流式读取与事件对象精简，但必须再次验证完整输出等价性。进程树 RSS 求和可能重复计算共享页，且定期采样不是硬隔离；需硬限制时使用容器内存限制。

解析改动对新启动的分析子进程生效；已运行的 Worker 需重启才能使用新的进程树内存监控。重启前应确认没有运行中或排队任务。
